Google 연결, 확인한 만큼 알려드려요.

누구의 Drive를 사용하나요?

앱의 ‘Google 계정 연결’ 버튼으로 로그인한 본인의 Drive를 사용합니다. 일반 사용자가 Cloud 콘솔, OAuth JSON 또는 개발자 계정을 준비할 필요는 없습니다. 메일을 보내는 SMTP 계정은 별도로 연결합니다.

요청하는 권한

현재 코드에서 요청하는 권한은 https://www.googleapis.com/auth/drive.file 하나입니다. 앱으로 만들거나 사용자가 앱에 허용한 파일을 위한 권한이며, 전체 Drive 또는 Gmail 권한을 요청하지 않습니다. Google이 비민감 권한으로 분류합니다. Google Drive 권한 안내

100명 제한이 있나요?

테스트 모드의 최대 100명 등록 사용자와, 승인되지 않은 민감·제한 권한에 적용되는 미검증 앱 사용자 한도는 다른 조건입니다. 배포자는 프로덕션 전환을 확인했고 현재 앱은 비민감 drive.file만 요청합니다. 다만 이 사실을 ‘무제한 사용자 검증’으로 표현하지 않습니다. 조직·계정 정책과 프로젝트 할당량은 별도로 적용됩니다. Google의 게시 상태·한도 설명

실제로 확인한 내용

2026년 11월 9일 Windows에서 테스트 목록에 없던 계정이라는 사용자 확인을 받고, 실제 브라우저 Google 로그인 → 64 KiB 파일 비공개 업로드 → 다운로드 SHA-256 일치까지 성공했습니다. 이메일을 보내거나 공개 공유하지 않았습니다. 기존 앱 설정과 분리된 보안 저장소를 사용했습니다.

이는 일반 계정 한 개의 성공 사례입니다. 모든 Google 계정·조직 환경, 100명을 넘는 규모, 실제 장기 토큰 갱신을 검증한 것은 아닙니다. Mac에서의 새 일반 계정 로그인도 별도 확인 대상입니다.

연결이 만료되면

앱은 토큰을 OS 보안 저장소에 보관하고 만료 시 갱신합니다. Google에서 갱신 권한을 거절하면 ‘다시 연결’로 안내합니다. 네트워크가 잠깐 끊겼다는 이유로 계정이나 전송 기록을 지우지 않습니다.

Drive의 저장 공간과 사용량

내 계정의 남은 저장 공간, Google API 할당량, 조직 정책이 적용됩니다. 제한 오류에는 재시도 안내를 표시합니다. 프로젝트별 실제 할당량은 배포자가 Google Cloud 콘솔에서 확인해야 하며 무제한 저장이나 전송을 보장하지 않습니다. Google Drive 사용량 제한

배포자가 관리할 사항

기존 프로젝트의 Audience(외부·프로덕션), Data Access(drive.file), Drive API 활성화, 홈페이지·개인정보처리방침·지원 연락처를 유지해야 합니다. 민감한 권한을 추가하면 검증 요구사항을 다시 확인해야 합니다. 브랜드·도메인 검증은 권한 검증과 구분합니다. Google 공개 앱 정책
